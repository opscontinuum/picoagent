# ASD STIG assessment addendum, 2026-09-09

The 2026-09-07 assessment ([assessment-2026-09-07.md](assessment-2026-09-07.md), findings in
[findings-2026-09-07.json](findings-2026-09-07.json)) left the checklist incomplete in two
ways this addendum closes: the eight findings it raised were remediated after it was written
and their determinations never updated, and thirty rules were never reviewed at all. The
original documents are kept verbatim as the point-in-time record; this addendum is the delta,
and the committed checklist ([picoagent-asd-v6r4.ckl](picoagent-asd-v6r4.ckl)) carries every
determination below, each marked with this date in its finding details.

**Scope note.** The 2026-09-07 assessment examined the tree before the plugin extraction
(PR #27): `examples/plugins/` then held ten plugins that now live in their own repositories
(`picoagent-plugins`, `es-doctor`, `stig-runner`, `iscp-author`). Determinations below are
made against `main` at the date of this addendum; finding details written on 2026-09-07 may
reference pre-extraction paths and are left as written, per this repository's rule that
records are annotated, not rewritten. The extracted plugins are separate assessable artifacts
now, each with its own tests.

**Assessed artifact:** `opscontinuum/picoagent`, an open-source, stdlib-only coding agent
harness developed in public. It is not a deployed DoD system; rules that bind a deploying
program, its ISSO, or its site are marked Not Applicable with that rationale, and become that
program's obligations when picoagent is deployed into one - this record is input to that
review, not a substitute for it (the same position `threat-model.md` takes for V-222655).

## Cadence

- **Every checkin:** the suite runs `tests/test_stig_assessment_record.py`, which fails the
  build if the checklist stops parsing, any rule returns to Not Reviewed, the checklist's
  Open set drifts from the register above, or the evidence a closed rule cites stops
  existing. That is the honest per-commit re-verification: the record's integrity and its
  evidence, mechanically. It is not a re-assessment, and does not claim to be.
- **Every release, and at the threat model's out-of-cycle triggers:** a human walks the
  determinations against the diff - the same cadence and triggers `threat-model.md` already
  states for itself. Procedure in [../../../tools/stig/README.md](../../../tools/stig/README.md).
- **Quarterly:** the DISA maintenance window (re-check for a new ASD release; V6R4 skips
  quarters, so absence of a new release is normal) and the CM access review (V-222631).
